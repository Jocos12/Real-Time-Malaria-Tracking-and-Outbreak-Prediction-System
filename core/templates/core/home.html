Kafka: streaming without losing a message

The Django API is the producer. A named consumer group reads the topic in parallel, and Kafka Connect sinks the same stream into storage automatically.

Topic and partitions

The topic is split into partitions. Records with the same key always land in the same partition, so their order is kept.

Consumer group

Several consumer instances share the partitions. Each partition is read by exactly one consumer of the group.

Offsets

An offset is the position of the last message read. It is committed, so a restarted consumer resumes where it stopped.

Kafka Connect

Sink connectors copy the stream to MySQL and to HDFS with no manual step.

Live demo of a rebalance

  1. Start consumer 1. It takes all partitions.
  2. Start consumer 2 in the same group. Partitions are split between the two.
  3. Stop consumer 2. Kafka rebalances and consumer 1 takes its partitions back.
  4. Check the lag. Run kafka-consumer-groups --describe to show offsets and lag: nothing is lost, nothing is read twice.

Two Spark MLlib models trained on our own data

Both are trained with an 80/20 train and test split, saved to HDFS, then used for batch scoring of every record.

Model 1: individual case risk

Random Forest100 treesmax depth 8

Input: age, region, gender, body temperature, ambient temperature, humidity, rainfall, number of symptoms. Output: 1 (likely positive) or 0.

Model 2: regional outbreak

Gradient Boosted Trees20 iterationsmax depth 5

Cases are grouped by region and 1-minute window (a demo-scale choice; production would use days). A window above the 75th percentile of positive cases is labeled an outbreak.
